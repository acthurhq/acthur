# PRD — Phase 7: Generator Engine

> **Status:** ready-for-agent · **Phase:** 7 of the implementation plan (PRD §21)
> **Governing ADRs:** 0005 (CLI-assembly injection) · contract model from Phase 4
> **Implementation note:** `docs/implementation/active/0005-phase-7-generator-engine.md`

## Problem Statement

Contracts are parsed, validated, diffed, and enforced at the proxy (Phase 4), and plugins register generators the kernel stores (Phases 5–6) — but nothing turns a contract into code. `acthur generate` is a stub. Phase 7 builds the generator engine: contract → template data → framework-native Go files, written idempotently under a `generated.lock`, with a test generated alongside every source file.

**Done when:** `acthur generate from-contract users.contract.yml` produces compiling Go code with tests inside a scaffolded go:fiber project (live witness: `go build ./... && go test ./...` green in the target node).

## Shared conventions (all slices)

- The unit of exchange stays `[]plugin.GeneratedFile` (Phase 6's type: Path/Content/Mode/Overwrite/MergeMarker). The pipeline produces them; the write engine persists them.
- Type mapping (contract → Go): `string`→string, `int`→int64, `bool`→bool, `timestamp`→time.Time, `ulid`→string (generated via the target's `internal/ids`), `email`→string (validated), `enum(a,b,…)`→string constant set, `array($Type)`→[]Type, `$Type`→reference into `types:`, trailing `?`→pointer. Constraints in parens (`required`, `max:N`, …) become validation in the generated handler.
- Generated files carry a header line `// Code generated by acthur; DO NOT EDIT above this line — edits below the marker survive regeneration.` only where merge semantics apply; plain files get `// Code generated by acthur from <contract>.contract.yml.`
- Tests are generated **alongside every source file** (same package, `_test.go`, table-driven, exercising the happy path + one validation failure per constrained field) and must pass inside the scaffolded project.
- Behavior tests first (TDD); parse every emitted `.go` file with `go/parser`; gold-standard test scaffolds a real go:fiber project (adapter `Scaffold` + `scaffold.ResolveScaffoldContext`), writes generated output in, and runs `go mod tidy && go build ./... && go test ./...`.

## Slices

### Slice 1 — Write engine + generated.lock (#48)
`internal/generate/` write engine: `WriteFiles(root, nodeID string, files []plugin.GeneratedFile) ([]Result, error)` honoring Overwrite/MergeMarker, plus **`generated.lock`** at project root (YAML: path → sha256 of last-generated content). Semantics: file absent → write + record; file present and hash matches lock → regenerate (safe, user never touched it); file present and hash differs from lock → **skip with a warning** (user-owned now) unless the file has a MergeMarker, in which case merge below the marker. Hoist `writeGeneratedFile` from `cmd/acthur/add.go` into this package and make `acthur add` use it (keep add's behavior; lock participation for add is a follow-up — record files it writes).
**Files:** `internal/generate/engine.go(+_test)`, minimal edits to `cmd/acthur/add.go`.

### Slice 2 — go:fiber template library + contract→code pipeline (#49)
`internal/generate/gofiber/`: contract (from `internal/contract`) → `[]plugin.GeneratedFile` for the target node: `internal/<name>/dto.go` (types: + endpoint input/output structs with validation tags/functions), `handler.go` (fiber handlers per endpoint: route, auth stub hook, input validation per constraints, error mapping from `errors:`), `service.go` (interface + skeleton), `repository.go` (pgx implementation skeleton for CRUD-shaped endpoints), `routes.go` (one `Mount(app, db)`), migration `migrations/NNNN_<contract>.up/down.sql` derived from `types:` (range 0400–0499), and a `_test.go` beside every source file. Entry point: `Generate(c *contract.Contract, ctx plugin.GeneratorContext) ([]plugin.GeneratedFile, error)`.
**Files:** `internal/generate/gofiber/` only (templates via go:embed).

### Slice 3 — CLI + `generate model` + live witness (main agent)
`acthur generate from-contract <file>` (resolve contract → pipeline → write engine, `--node` flag as in add); `acthur generate model <Name> <field:type>...` (model struct + migration + test via the same engine); live witness per done-when.

## Out of scope
Non-fiber adapters, client SDK generation, frontend/admin generation, regeneration-on-watch, plugin-registered generators execution beyond what Phase 6's `acthur add` already does.
